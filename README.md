## 技术原理

RAMMap 是原生 Win32 程序，界面文字分布在两处：

1. **资源段（`.rsrc`）**：菜单模板、对话框模板
2. **只读数据段（`.rdata`）**：标签页名、列头、提示消息等字符串常量

本工具做的是**精确的字符串数据替换**，绝不触碰代码：

| 目标 | 做法 | 关键点 |
| --- | --- | --- |
| 菜单资源 | 解析原模板 → 替换文本 → **按原格式重新序列化** | 实测确认了菜单模板格式（popup 项无 ID 字段），重建后 522→406 字节原地覆盖，尾部补零；Alt 加速键完整保留 |
| 对话框资源 | 译文 + **尾部空格填充**，保持字段物理长度不变 | 不能填 `\0`，否则模板解析器会把后续控件结构解析错位 |
| 数据段字符串 | 译文 + `\0` 填充，保持字节长度不变 | 译文超长一律拒绝替换，绝不越界写坏相邻数据 |

**安全设计**（每一条都有自动化校验）：

- 每个替换必须通过**完整字符串边界校验**（是别的大字符串的前缀/后缀一律不算命中），避免把含 `\r\n` 的多行消息切碎
- **`.text` 代码段命中即跳过**并告警
- 构建后可一键验证：`.text` / `.pdata` / `.reloc` 段 SHA256 与原版**完全一致**；菜单与对话框能被系统 API 正确加载
- 工具自身经过端到端回归：汉化产物与参考产物**逐字节一致**，还原后与原版**哈希一致**

## 常见问题

**Q：支持哪个版本？**
A：针对 RAMMap **v1.63** 的字符串布局编写；其他版本会尽量匹配，匹配不上的条目保留英文并在日志中提示。

**Q：汉化后数字签名失效？**
A：正常现象。任何修改过的 exe 签名都会失效，不影响运行。

**Q：杀毒软件报毒？**
A：凡"修改 exe"的工具都易被启发式误报。本项目源码全部开放，可自行审计、自行编译——这也是我们坚持开源的原因。

**Q：为什么不做"汉化版 exe"直接分发？**
A：Sysinternals 许可协议明确禁止再分发该软件（官方 FAQ 原文："我们不提供任何分发许可证，即使第三方免费分发它们也是如此"）。本项目只分发**工具**，软件本体请从官方获取。

**Q：能用来汉化 Process Explorer / Autoruns 等其他 Sysinternals 工具吗？**
A：不能直接套用。本项目针对 RAMMap 编写；其他工具需要重新做字符串分析（`tools/` 里的流程可复用）。
